# Rigs of Rods for iOS

[![Latest Release](https://img.shields.io/github/v/release/wayl-t/ror-ios?label=latest&color=blue)](https://github.com/wayl-t/ror-ios/releases)
[![Build Status](https://img.shields.io/github/actions/workflow/status/wayl-t/ror-ios/build-ror-ios.yml?branch=main)](https://github.com/wayl-t/ror-ios/actions)
[![License](https://img.shields.io/badge/license-GPLv3-green.svg)](https://www.gnu.org/licenses/gpl-3.0)

This is an **unofficial native iOS port** of [**Rigs of Rods**](https://www.rigsofrods.org/), the open source soft-body physics vehicle simulator. 

**All credit for the original game goes to the [Rigs of Rods Team](https://www.rigsofrods.org/credits).** This repository adapts the full upstream game codebase for iOS (arm64) with touch controls, a custom build pipeline, and sideloadable IPA distribution.

> This is not a remake. The full Rigs of Rods source is compiled here with iOS-specific patches (`patches/ror/apply_ios_patches.py`).

Сборка полностью автоматизирована на **бесплатных** macOS-раннерах GitHub Actions — без Mac, без платного Apple Developer аккаунта. Установка через сайдлоад (SideStore, ESIGN, Sideloadly).

## Статус

✅ **Полностью играбельно** — меню, выбор карты/машины, вождение, пеший режим  
✅ **Сенсорное управление** — виртуальный руль, педали, панель управления  
✅ **Собственные моды** — можно добавлять `.zip` через папку `Files`  
🚀 **Актуальная версия — [rtss30](https://github.com/wayl-t/ror-ios/releases/latest)**

Каждый релиз автоматически собирается тегом `rtssNN` и проходит **30 автоматических проверок** через `verify_ipa.py`.

## Что исправлено в rtss30

Ключевые проблемы, решённые в текущем релизе:

- **чёрный аватар** в пешем режиме. Тени на iOS выключены (PSSM-программы
  не поддерживаются GLES2), поэтому подключается вариант
  `managed_materials/shadows/pssm/off`, и именно из него материал персонажа
  наследует технику `Shadows/managed/base_receiver`. В варианте «с тенями» у
  этой техники есть `ambient 1 1 1 1` / `diffuse 1 1 1 1`, а в варианте
  «без теней» пасс **пустой** — OGRE по умолчанию считает ambient чёрным, и
  тело рисуется сплошной чёрной кляксой, хотя текстура нормальная. Теперь
  пустому пассу задаются те же константы освещения. Заодно убран пасс
  `ColorChange` из `tracks/character`: он красит тело цветом игрока через
  fixed-function смешивание, которое на GLES2 превращается в умножение меша
  на `(0,0,0)`. Также исправлен нормальный трансформ в `FFPLib_Lighting.glsl`
  (нормаль больше не умножается с `w=1.0`).
- **моды из репозитория не ставились**. Загрузка модов через встроенный
  репозиторий писала скачанный архив в `mods/*.part`, но переименование
  `.part` → `.zip` на iOS падало/не отрабатывало корректно, из-за чего архив
  оставался `.part` и `ParseSingleZip` его не подхватывал. Теперь переименование
  делается через `std::filesystem::rename` с фолбэком `Ogre::FileSystemLayer::renameFile`,
  копированием+удалением при неудаче, с проверкой наличия финального `.zip`
  и подробным логом `[RoR|Repository] install: ...`.

### Дашборд и репозиторий модов

- **Мобильный HUD** — вместо desktop-панели приборов показываются только скорость и передача; управление разнесено по зонам большого пальца.
- **Репозиторий модов в игре** — кнопка **REPO** в главном меню открывает встроенный браузер модов с загрузкой прямо из игры через `NSURLSession`. Превью миниатюр пока недоступны.

Проверка `verify_ipa.py` теперь требует, чтобы в собранном IPA лежал материал
персонажа **без** пасса `ColorChange` и чтобы `shadows/pssm/off` был освещённым
— раньше эти правки были написаны, но не подключены в `main()`, и в собранной
версии молча отсутствовали.

История: в **rtss22** машина с мягким кузовом (flexbody) роняла приложение при
спавне — мод F-150 и штатный DAF Semi одинаково, потому что падал не мод, а
код, который его грузит (разбор — §7.39 в `PORT_FINDINGS.md`). В `rtss21`
дополнительно была нерабочей перезапись CVar'ов после `RoR.cfg` (§7.38), а в
более старых сборках не было и самого фикса материалов.

## Что сделано

### Конвейер

**Важно: в репозитории есть два разных IPA.** Игровую сборку создаёт
`build-ror-ios.yml` — она компилирует исходники Rigs of Rods и публикует
`RoR-ios.ipa`. Workflow `build-ipa.yml` и скрипт `build_ipa.sh` собирают только
небольшое приложение-проверку из `app/`: оно подтверждает работу Xcode,
упаковки и доставки IPA, но **не содержит игру**. Его релиз `pipeline-check`
предназначен только для проверки конвейера; для установки игры используйте
релиз `rtssNN` (или другой тег, переданный в `build-ror-ios.yml`).

- `build-ror-ios.yml`: закреплённый коммит RoR (`d426a5c5`) + зависимости
  (отдельный переиспользуемый прогон `build-ios-deps.yml`) → сборка arm64
  → ad-hoc подпись → IPA → публикация в Releases.
- `verify_ipa.py`: 30 автоматических проверок на каждый IPA — стартовый путь
  (skeleton.zip, шейдеры MyGUI/RTSS, контент), иконки, наличие сенсорного
  управления в бинарнике, а также обходы, без которых на GLES2 ничего не
  работает (в частности, перестановка CVar'ов после `RoR.cfg`, исправленный
  файл материалов и исправленный `readData()` в OGRE). Падает громко, если
  сборка что-то потеряла.
- Основной путь доставки — ссылка на GitHub Release (обходит файрволы);
  запасной — `gh run download` (см. ниже).
- Правки в зависимостях (OGRE) живут в `build-ios-deps.yml`, а не в
  `build-ror-ios.yml`. После такой правки нужно **сначала** прогнать
  `build-ios-deps.yml`, а затем указать его номер в `build-ror-ios.yml`
  (`-f deps_run_id=<номер>`), иначе сборка возьмёт «последний удачный» SDK и
  правка молча не попадёт в IPA (именно так один раз проехали с GLSL-препроцессором).
  Именно этот случай сторожит проверка `readData()` в `verify_ipa.py`.
- Запуск сборки: из каталога репозитория
  `gh workflow run build-ror-ios.yml --ref main -f deps_run_id=<номер> -f release_tag=rtssNN`.
  Тонкость с правами: fine-grained PAT dispatch не умеет (GitHub отвечает
  `403 Resource not accessible by personal access token`), нужен обычный
  `gh`-логин со scope `repo`. Правка самих файлов в `.github/workflows/`
  требует ещё и scope `workflow`.

### Игра

- Полный RoR на устройстве: главное меню, селектор карт и машин, настройки —
  всё открывается и управляется касаниями.
- Интерфейс адаптирован под телефон: шрифт и виджеты ImGui рисуются в
  десктопном размере (1×) — прежнее увеличение 1.5×/2× оказалось на телефоне
  слишком крупным. Ручка всего одна: `style.ScaleAllSizes()` и множитель
  шрифта в `patches/ror/apply_ios_patches.py`.
- Иконка приложения: генератор `patches/ios/make_app_icon.py` (чистый Python),
  набор для iPhone и iPad в бандле и в `Info.plist`.

### Сенсорное управление

- Вождение: круглый руль, педали с пиктограммами, компактный HUD со скоростью
  и передачей, ряд быстрых действий.
- Верхняя панель доступна и в машине, и в свободной камере: меню, спавн
  машины, репозиторий модов и страницы систем автомобиля. Спавн использует
  обычный селектор RoR со всеми его режимами.
- Панель **VEH** открывает крупные страницы LIGHTS / DRIVE / EXTRAS, чтобы
  настройки машины не занимали экран мелкой сеткой.
- Режим свободной камеры: круглый джойстик, свайп по сцене для обзора,
  кнопки высоты и входа в машину — все действия показаны иконками.
- Главное меню, пауза, выбор карты/машины, настройки, управление и репозиторий
  занимают экран адаптивно; кнопки увеличены для касаний.

### Контент

- В IPA уже лежат три мода: террейн `simple2.terrn2`, машина **Daf Semi** и
  машины `agora`.
- **Свои моды добавляются без пересборки**: положите любой `.zip` (машина,
  карта) в папку `content/` приложения через «Файлы» или кабель — RoR монтирует
  каждый zip автоматически (`UIFileSharingEnabled`). Работает и на устройстве:
  папка видна в *На моём iPhone › Rigs of Rods*.

### Исправленные проблемы (по логам устройства)

- Чёрное небо → режим неба по умолчанию SANDSTORM.
- Невидимое меню → обновление shader-параметров ImGui-оверлея под GLES2.
- Касания не доходили до меню → мост тач→мышь→ImGui.
- **Сломанный меш персонажа**: материал и меш загружаются, но предыдущие
  попытки исправить его рендеринг не помогли. В iOS-режиме локальная модель
  больше не регистрируется для отрисовки; вместо пешего персонажа игра сразу
  использует свободную камеру. Джойстик FLY двигает камеру, касание сцены
  меняет направление, кнопки UP/DOWN регулируют высоту. Логический объект
  игрока остаётся для совместимости с игровым кодом.
- Тени выключены, а режим неба и альтернативные материалы машин принудительно
  выставляются после загрузки `RoR.cfg` (`patch_cvar_ios_overrides()`), чтобы
  сохранённые значения не отменяли настройки портированной сборки.
- **Краш при спавне любой машины с мягким кузовом**: `FlexBody` при создании
  читает вершины и нормали каждого меша своего мягкого тела из видеобуфера
  через `Ogre::GLES2HardwareBuffer::readData()`, а тот в OGRE 1.11.6 зовёт
  `glMapBufferRangeEXT()`, **не привязав перед этим буфер** (соседний
  `lockImpl()` привязывает — здесь этого не было). В GL ES 2
  `glMapBufferRangeEXT()` отображает «то, что сейчас привязано к цели»: на
  телефоне он вернул `NULL`, и `memcpy()` пошёл читать по адресу 0. Трасса
  показывает это буквально: `addr=0x0`, `pc` вне образа (там `memcpy`), `lr`
  внутри `readData`. Поэтому падала **любая** машина с flexbody — и мод
  F-150, и штатный DAF Semi, а «краш мода» был лишь симптомом. Исправлено
  патчем OGRE в `build-ios-deps.yml`: буфер привязывается перед отображением,
  а неудачное отображение даёт исключение вместо падения;
  `verify_ipa.py` требует след этого патча в бинарнике. Как расшифровать `lr`
  из своей же трассы без Mac — §7.39 в `PORT_FINDINGS.md`.
- **Материалы машин уходили в «nicemetal»/Cg**: материалы машины с картой
  бликов брались из «nicemetal»-вариантов (`managed/..._nicemetal.material`), а
  те держатся на Cg (`NiceMetal_VS_mm`, `profiles vs_1_1 arbvp1`). Cg в этот
  порт не собирается (мёртвый NVIDIA-тулкит), поэтому такие материалы
  оставались «без поддерживаемых техник». На iOS теперь принудительно включён
  `gfx_alt_actor_materials=true` — машины берут обычные
  `managed/.../specular*` материалы, для которых шейдеры генерирует RTSS.
  Важная деталь, на которой легко обжечься: значение нужно выставлять через
  `setVal()`, а не `setStr()`. `CVar::setStr()` сохраняет строку и **обнуляет**
  числовое поле, а все читатели этих CVar'ов (`getEnum<>()`, `getBool()`) смотрят
  именно на него — то есть `setStr("true")` оставлял bool-CVar выключенным (так
  было в сборке rtss21).
- **Битая строка в материалах**: в
  `managed_mats_vehicles_transparent_nicemetal.material` было
  `texture_alias specular_tex 2d` (у `texture_alias` не бывает второго
  аргумента). Парсер скриптов ругался и бросал остаток файла, так что часть
  материалов вообще не определялась. Исправлено.

## Чего нет / ограничения

- **Загрузка модов из официального репозитория** (`forum.rigsofrods.org`)
  внутри игры: селектор использует libcurl, которого нет в наборе iOS-
  зависимостей. Требует добавления curl в `build-ios-deps.yml` — см. дорожную
  карту. Свои моды через «Файлы» работают уже сейчас (см. выше).
- **Тени не рисуются** (причина — выше, «Сломанный меш вместо человека»). На
  iOS значение `gfx_shadow_type` сбрасывается в `NONE` при каждом запуске, так
  что включить PSSM из настроек не получится — на текущем GPU-пути он всё
  равно не соберётся.
- **Caelum/SkyX не собираются** — небо только Sandstorm.
- **Мультиплеер на устройстве не протестирован** (SocketW собран без OpenSSL).
- Предупреждения в логе `RoR.log`, не влияющие на игру: `en/ror.mo`,
  fontdef/legacy `.os`, `BindAttributeLocation`.
- Сайдлоад: бесплатный Apple ID → переподпись каждые 7 дней; ~3–4 ГБ RAM
  (лимит виден в приложении; поднять можно через SideStore + GetMoreRam).

## Как установить

1. **Скачайте IPA** — откройте [последний релиз](https://github.com/wayl-t/ror-ios/releases/latest) в Safari на iPhone или на ПК.
2. **Установите через сайдлоад** — используйте один из инструментов:
   - [SideStore](https://sidestore.io/) — сайдлоад прямо с телефона, автоматическое продление
   - [Sideloadly](https://sideloadly.io/) — через ПК (macOS/Windows/Linux)
   - [ESIGN](https://esign.yyyue.xyz/) — через веб/приложение на устройстве
3. **Авторизуйтесь** своим обычным Apple ID при установке. При бесплатном Apple ID приложение нужно будет переподписывать каждые 7 дней.

> **Проблема с загрузкой?** Если `release-assets.githubusercontent.com` долго висит — скачайте IPA через `gh run download` из артефактов Actions.

## Диагностика на телефоне

Если игра падает или что-то не рисуется, самое полезное — файл
`ror-trace.log` в *Файлы › На моём iPhone › Rigs of Rods*. Он пишется
небуферизованно, строка за строкой, поэтому в нём целы и последние строки
перед падением; `RigsOfRods/logs/RoR.log` буферизуется и хвост теряет — на
него лучше не рассчитывать.

Что искать в трассе:

- `[RoR|iOS] cvars after RoR.cfg: …` — что лежало в конфиге и что порт
  переставил принудительно. Полный формат:
  `[RoR|iOS] cvars after RoR.cfg: sky <было>-><стало>, shadow <было>-><стало>, alt_actor_materials <было>-><стало>`.
  Справа стоят значения, прочитанные из самих CVar'ов уже **после** перестановки,
  так что строка показывает, что реально действует, а не что задумывалось.
  Норма — `sky 0->0, shadow 0->0, alt_actor_materials 1->1`; если слева у
  `shadow` стоит `1`, на телефоне лежал `RoR.cfg` с включёнными PSSM-тенями —
  ровно причина того, почему сборки до rtss21 «не видели» исправления
  персонажа; если справа у `alt_actor_materials` стоит `0`, материалы машин
  уходят в Cg-варианты `_nicemetal`.
- `startup: …` — фаза запуска: по последней строке видно, где приложение
  остановилось.
- `[fatal]` / `[crash]` — необработанное исключение или SIGSEGV с адресом.
  Перед падением печатается база образа (`exe base 0x…`), а строка `[crash]`
  содержит `pc` и `lr`; смещение `lr` от этой базы можно превратить в имя
  функции прямо из скачанного `.ipa` — таблица символов в бинарнике не
  вырезана, Mac для этого не нужен (как это делается — §7.39 в
  `PORT_FINDINGS.md`). Кстати, если `pc` вне образа, а `lr` внутри — виноват
  вызов системной функции из нашей.

Тот же файл (`RoR.log`) и папка `content/` доступны кабелем или в приложении
«Файлы».

## Устройство репозитория

```
ror-ios/
├── .github/workflows/
│   ├── build-ror-ios.yml       # основная сборка: RoR → IPA → Release
│   ├── build-ios-deps.yml      # iOS-зависимости (переиспользуются)
│   └── build-ipa.yml           # legacy: дымовой тест вехи 0 (использует app/)
├── patches/
│   ├── ror/apply_ios_patches.py  # все правки исходников RoR под iOS
│   ├── ios/make_app_icon.py      # генератор иконки (чистый Python)
│   └── verify_ipa.py             # 30 проверок готового IPA
├── PORT_FINDINGS.md              # разбор найденных проблем
└── app/, build_ipa.sh            # legacy вехи 0 (не основной конвейер)
```
